Problems and solutions

Aeolis — Module
Aeolis

A Julia port of AeoLiS, the process-based model of supply-limited aeolian sediment transport (de Vries et al. 2023): wind and its perturbation by topography, the shear velocity threshold with moisture, salt, sheltering and non-erodible layers, equilibrium transport, multiple sediment fractions in bed layers, tides, waves, runup, groundwater and moisture, avalanching, vegetation, sand fences and dune erosion.

A model is an AeolisProblem built from AeolisParameters (or an AeoLiS configuration file, read_config) and solved with the SciML interface (init, step!, solve) by a scheme (EulerBackward, CrankNicolson, EulerForward) and a transport solver (Trunk, Pieter, SteadyState). Loading NCDatasets enables write_netcdf.

Aeolis.AeolisProblem — Type
AeolisProblem(p::AeolisParameters; tspan=(p.tstart, p.tstop), u0=nothing)
AeolisProblem(configfile::AbstractString; kwargs...)

An AeoLiS simulation from tspan[1] to tspan[2]. Like AeoLiS, steps are taken while the time is at most tspan[2]. u0 replaces the initial state built from the parameters. A configuration file is read with read_config.

CommonSolve.init — Method
init(prob::AeolisProblem, alg=default_algorithm(prob.p); saveat=prob.p.output_times,
     save_vars=prob.p.output_vars, save_stats=prob.p.output_types, callback=nothing,
     tstops=Float64[], dt=-1, fixed=Dict(), restart=nothing, restart_every=prob.p.restart,
     restart_file=nothing, rng=Random.Xoshiro(0), T=Float64)

An AeolisIntegrator for prob. Output follows AeoLiS: a save whenever at least saveat seconds have passed since the last one (and at t == 0); a vector of times saves at those times, which are added to tstops. save_vars are state variables, optionally with a statistic suffix (:zb_avg); save_stats adds statistics to every saved variable. dt is the requested step (-1 for the dt parameter). Variables in fixed keep the given values (AeoLiS hotstart files). restart is a file written by save_restart.

Aeolis.AeolisIntegrator — Type
AeolisIntegrator

The state of a running simulation, from init(prob, alg): the state u (an AeolisState), the time t, the last step dt, the model with parameters model.p, and the saved output. integ[:zb] reads a state variable; step! advances it.

source
Aeolis.AeolisSolution — Type
AeolisSolution

The result of solving an AeolisProblem: output times t, and for every saved variable an array with time as the last dimension. sol[:zb] gives the bed level at every output time, sol[:zb, k] at the k-th; statistics are named :zb_avg, :zb_max and so on. sol.u is the final state, sol.model the model, sol.retcode a SciMLBase ReturnCode.

Supertype of the numerical schemes: EulerBackward, CrankNicolson and EulerForward, each with a transport solver and an optional LinearSolve.jl algorithm for the sparse systems.

Aeolis.EulerBackward — Type
EulerBackward(solver=Trunk(); linsolve=nothing)

The implicit Euler (AeoLiS default) scheme with transport solver solver. linsolve is a LinearSolve.jl algorithm for the sparse systems (nothing lets LinearSolve choose).

source
Aeolis.CrankNicolson — Type
CrankNicolson(solver=Trunk(); linsolve=nothing)

The Crank-Nicolson scheme with transport solver solver. linsolve is a LinearSolve.jl algorithm for the sparse systems (nothing lets LinearSolve choose).

source
Aeolis.EulerForward — Type
EulerForward(solver=Trunk(); linsolve=nothing)

The explicit Euler, with the time step limited by the CFL number scheme with transport solver solver. linsolve is a LinearSolve.jl algorithm for the sparse systems (nothing lets LinearSolve choose).

Aeolis.Trunk — Type
Trunk()

The default AeoLiS transport solver: an upwind discretisation solved as a sparse linear system per fraction (solver = trunk).

source
Aeolis.Pieter — Type
Pieter()

The finite-volume AeoLiS transport solver with fluxes on cell faces (solver = pieter).

source
Aeolis.SteadyState — Type
SteadyState()

The steady-state AeoLiS transport solver, sweeping the grid upwind (solver = steadystate).

Aeolis.read_config — Function
read_config(file; kwargs...)

The AeolisParameters of an AeoLiS configuration file, with files loaded relative to the file's directory. Keywords override entries of the file. Keys that AeoLiS ignores (and nfractions, which follows from grain_size) are skipped with a warning listing them. output_file defaults to the configuration file name with extension .nc, and h to z.

source
Aeolis.write_config — Function
write_config(file, p::AeolisParameters)

Write p as an AeoLiS configuration file. Input arrays are written to text files next to it (bed_file to bed.txt, and so on) in the layout AeoLiS reads.

source
Aeolis.run_config — Function
run_config(file; outputfile=nothing, kwargs...)

Run the AeoLiS model of a configuration file, like aeolis run file: solve with the scheme and solver of the file and, if NCDatasets is loaded, write the output to outputfile (the file's output_file). Returns the AeolisSolution. Keywords go to solve.

source
Aeolis.write_netcdf — Function
write_netcdf(file, sol::AeolisSolution)

Write the saved output of sol to a netCDF file with the variables, dimensions and attributes of AeoLiS output (transects as one row). Needs NCDatasets.jl to be loaded.

source
Aeolis.load_array — Function
load_array(file; spatial=false)

The numbers in a text file as AeoLiS's numpy.loadtxt reads them: a vector for a single row or column, otherwise a matrix (transposed for spatial files, so that x is the first dimension). Complex numbers are allowed (masks).

Raised when the parameters do not describe a runnable model, for example when the grid or bed is missing or an input series has too few columns.

source

Raised when a method or boundary parameter names an option that does not exist; allowed lists the options that do.

source
Aeolis.UnsupportedOptionError — Type
UnsupportedOptionError(parameter, value, reason)

Raised when an option exists in AeoLiS but has no implementation there either (for example a cross-shore circular boundary or the dry-layer threshold), or is not available in this port.
